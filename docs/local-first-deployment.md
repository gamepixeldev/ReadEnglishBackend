# 本地开发与上线流程

## 环境约定

- 本地：PHP 8.4、Laravel 13、现有 MySQL 8.0 中**新建的独立数据库**。不升级或修改本机其他项目的 MySQL 数据库。
- 首次上线：自有云服务器上独立的 PHP 8.4 环境与 MySQL 8.4 LTS 数据库。服务器系统和现有站点情况确认后再写具体安装步骤。
- 数据库版本差异以 MySQL 8.0 能运行的迁移和 SQL 为开发基线；首次上线前必须在 MySQL 8.4 上重新验证。
- `.env`、数据库密码、用户上传的媒体文件、数据库备份不进 Git。生产 `.env` 单独配置；不要直接复制本地 `.env`。

## 开发阶段

本地管理后台入口为 `http://localhost:8000/admin/login`。登录后可在概览查看内容数量，在独立的文章、单词列表中搜索和筛选，再进入编辑页维护正文、详解、重点词及发布状态。旧的 `/admin/content` 地址会跳转到对应的新页面。管理员账号由 `php artisan content-admin:provision` 首次生成，不在仓库中保存密码。

1. 使用 Laravel 迁移维护表结构，不能只在数据库管理工具中手动改表；迁移文件随 PHP 代码一起提交。
2. 在独立的本地 MySQL 8.0 库执行迁移、导入可发布的内容并做接口测试。自动化测试仍可使用 SQLite 内存库，但不能替代 MySQL 集成测试。
3. 测试账号、模拟学习记录、未获授权或未发布的内容不得进入正式导出数据。
4. 内容资源若存在图片、音频或上传文件，单独整理并迁移；SQL 导出文件不包含这些文件。

## 第一次上线（线上库为空时）

1. 备份服务器现有站点与数据库，确认新项目使用独立站点目录、独立数据库和独立数据库账号。
2. 在本地完成全部功能、发布内容检查及 MySQL 8.4 兼容验证后，从专门准备的**干净内容库**导出 SQL。此库不得混入测试用户和模拟进度。
3. 在线上新建空数据库，导入 SQL，并确认 `migrations` 表与代码中的迁移文件一致；导入后检查表数量、内容数量和字符集。MySQL 官方支持通过逻辑导出/导入完成 8.0 到 8.4 的迁移。
4. 上传 Laravel 代码和锁定的依赖版本；在服务器安装 PHP 依赖，配置生产 `.env`、稳定的生产 `APP_KEY`、数据库连接、文件权限和 HTTPS。Web 根目录必须指向本项目的 `public`，不能指向项目根目录。
5. 验证 `/up`、公开内容接口、登录、完成记录、管理端发布，以及图片/音频资源，然后再切换正式域名。

## 上线后更新

**不能再次用本地整库 SQL 覆盖线上库。** 线上已经产生用户、收藏、学习记录和进度，本地整库导入会破坏这些数据。

- 代码变更：上传新代码和 `composer.lock`，在备份线上数据库后执行尚未运行的 Laravel 迁移，并验证接口。
- 内容变更：文章和单词通过管理后台编辑、发布；其他内容模块的管理界面将在对应功能开发时接入。如需批量导入，只导入明确的内容表并做冲突检查，不触碰用户数据表。
- 生产备份：定期把数据库备份保存到服务器之外，并实际演练恢复。部署前另做一次可恢复的快照。
- 生产 `APP_KEY` 必须保持稳定；不随每次上传代码重新生成。

这份文档是流程约束，不是现在就执行导出、导入或部署的授权。具体命令要在本地库、服务器系统和已有站点确认后编写并验证。
